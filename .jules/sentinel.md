## 2026-07-03 - Path Traversal and Insecure Pickle Deserialization in Experimental Dataset Nodes
**Vulnerability:** User-controlled folder names and filename prefixes in experimental dataset nodes allowed path traversal outside the designated input/output directories. Additionally, loading serialized dataset shards via `torch.load` without `weights_only=True` created a Remote Code Execution (RCE) risk through malicious pickle payloads.

**Learning:** Path sanitization must be strictly enforced at boundary layers when processing user-defined directory names or filenames. Relying on `os.path.join` alone is insufficient because path segments containing traversal characters (like `..`) can escape parent directory boundaries. Furthermore, `torch.load` uses Python's `pickle` module by default under the hood, making it vulnerable to RCE if loading untrusted files. Enforcing `weights_only=True` restricts deserialization to safe data types (like tensors and basic structures) and mitigates this risk entirely.

**Prevention:** Always validate resolved paths against target base directories using a robust `safe_join` utility employing `os.path.commonpath`. Ensure all user-controlled filename prefixes are sanitized with `os.path.basename`. Lastly, always specify `weights_only=True` in `torch.load` calls when deserializing PyTorch models or data structures that do not strictly require execution of arbitrary user-defined code.
