## 2025-02-18 - Internal Files Route Exception Leakage and Denial of Service
**Vulnerability:** The `/internal/files/{directory_type}` endpoint attempted to perform directory scans without ensuring that the resolved directory path was not `None` or that it actually existed on the filesystem. This could result in unhandled `TypeError` or `FileNotFoundError` exceptions being thrown, leaking stack traces and causing Denial of Service (DoS) risks.
**Learning:** Functions that resolve directory locations dynamically (such as `get_directory_by_type`) can return `None` or return paths that are not initialized/created on disk. Route handlers must never assume directory paths are valid or exist without defensive checks.
**Prevention:** Always validate resolved directory paths using defensive checks like checking for `None` and confirming existence using `os.path.isdir()` prior to calling standard library operations like `os.scandir()`. Return a clear `404 Not Found` response with a JSON error payload for missing or unconfigured directories.
